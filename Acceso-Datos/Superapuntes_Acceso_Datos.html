Cómo entender un ejercicio y encaminarlo

Antes de escribir nada, contesta estas 6 preguntas. Te llevan de un enunciado largo a un esqueleto que ya sabes hacer.

  1. 1 · ¿Qué ENTRA y qué SALE?Subraya los ficheros y su extensión. Eso te dice la herramienta: .txt/.csv → BufferedReader/Writer · .dat con objetos → ObjectStream · .dat con «cada registro ocupa N bytes» → RandomAccessFile/DataStream · .xml → DOM · .json → Gson · tablas → JDBC. Si entra uno y sale otro, es una migración.
  2. 2 · ¿Cuál es el «objeto»?Cada línea, registro, <elemento> o { } es un objeto. Haz una clase con un atributo por dato (nombre, tipo, nivel…). Si un dato se repite (varios teléfonos, varios tipos) → List<String>. Si es contar o buscar por código → Map.
  3. 3 · ¿Qué funciones te pide?Copia tal cual los nombres y parámetros del enunciado (anyadirVotos(String partido, int votos)). El main solo llama a las funciones con los datos de prueba del enunciado.
  4. 4 · Escribe los pasos como comentariosAntes de escribir código: // 1 leer // 2 buscar // 3 cambiar // 4 guardar // 5 mostrar. Casi todo ejercicio es cargar → procesar → guardar/mostrar.
  5. 5 · Copia la plantilla y adaptaBusca en la tabla de pistas de abajo qué sección es, copia el esqueleto y cambia los nombres. No escribas desde cero lo que ya está aquí.
  6. 6 · Comprueba la salida EXACTAEjecuta con los datos del enunciado y compara letra a letra los mensajes (puntos, mayúsculas, «votos»). Mira también los casos raros: fichero que no existe, vacío, elemento que no está.

1 · La clase molde: Ejercicio_Pokemon

Cómo funciona
  1. La clase es el «molde»: cada objeto guarda nombre, tipo y nivel (atributos private).
  2. El constructor rellena los datos al hacer new. this.nombre es el atributo; n es el parámetro.
  3. Getters para leer los datos desde fuera y un setter para cambiar el nivel.
  4. toString decide qué sale al imprimir. Con @Override encima, si lo escribes mal Eclipse avisa (si no, sale Clase@1b6d3586).
  5. implements Serializable permite guardarlo entero en un .dat. Sin él salta NotSerializableException.
Truco Eclipse lo genera solo: botón derecho → Source → Generate Constructor using Fields / Generate Getters and Setters / Generate toString().

2 · Contar con un Map (ejercicio de las IPs)

Cómo funciona
  1. La IP es la clave del mapa y las veces que sale es el valor. No hace falta una variable contador.
  2. Por cada IP, getOrDefault(ip, 0) dice cuántas llevaba (0 si es nueva).
  3. put(ip, veces + 1) guarda una más: si la clave ya existe, sustituye el valor viejo.
  4. Al final se recorre keySet() y se imprime cada IP con get(ip).

JDBC: conectar y consultar

JDBC es la forma estándar de hablar con una base de datos desde Java. Todo lo que usas viene de java.sql: Connection (la conexión), PreparedStatement (la consulta), ResultSet (las filas que devuelve) y SQLException (el error).

ResultSet desplazable: contar antes del while

Por defecto el ResultSet es TYPE_FORWARD_ONLY: solo hacia delante. Para moverlo hacia atrás o saltar, créalo así:

MétodoQué hace
next() / previous()avanza / retrocede una fila
first() / last()primera / última fila
beforeFirst() / afterLast()antes de la primera / después de la última (para recorrer con next / previous)
absolute(n)fila n desde el principio; absolute(-1) es la última
relative(n)n filas desde donde estás (negativo = atrás)
getRow()nº de la fila actual (0 si estás fuera)

Tipos: TYPE_FORWARD_ONLY (por defecto), TYPE_SCROLL_INSENSITIVE (moverse; no ve cambios de otros), TYPE_SCROLL_SENSITIVE (no existe en MySQL). Concurrencia: CONCUR_READ_ONLY (por defecto) o CONCUR_UPDATABLE.

Cuidado Si llamas a last() con un ResultSet FORWARD_ONLY salta una SQLException. Y si llamas a getRow() después de que el while termine, devuelve 0, porque el cursor ya está fuera.
Truco Para contar, a veces es más simple un SELECT COUNT(*) aparte, o un contador++ dentro del while si el total se imprime al final.

Modificar desde el ResultSet (CONCUR_UPDATABLE)

Para borrar la fila actual: rs.deleteRow(). Para insertar: rs.moveToInsertRow(), los updateXxx y rs.insertRow(). La tabla necesita clave primaria y el SELECT debe ser de una sola tabla.

Transacciones: commit y rollback

Por defecto cada sentencia se guarda sola (autocommit). Si lo desactivas, los cambios solo se guardan cuando llamas a commit(); si cierras la conexión sin hacerlo, se descartan.

Truco Mientras pruebas un ejercicio que hace UPDATE, pon setAutoCommit(false) y no hagas commit: verás el resultado en consola pero la base de datos queda como estaba y puedes repetir la prueba. Quítalo cuando funcione.
Cuidado Si usas pool y pones autocommit a false, esa conexión vuelve al pool así. dbcp2 la restaura por defecto, pero no está de más dejarla en true al acabar.

Receta para cualquier ejercicio

Todos los ejercicios del examen modelo tienen la misma forma: comprobar los casos raros, mostrar, y si toca, modificar. Antes de escribir código, escribe los pasos como comentarios.

Secuencial (lo más habitual)

Cada consulta es un paso. Guarda en variables lo que necesites para los siguientes y sal con return en cuanto algo falle, así no acabas con ifs anidados.

Anidado (consulta dentro del bucle)

Solo cuando por cada fila de la primera consulta necesitas otra consulta: «para cada empleado, quién le reporta», «para cada pokemon, sus tipos». Prepara el PreparedStatement de dentro fuera del bucle y en el bucle solo cambias el parámetro.

En el examen Si una sola consulta con JOIN te da 0 filas, no sabes si es porque no existe la cosa o porque existe pero no tiene relacionados. Para distinguir los dos casos, consulta primero la tabla principal sola. Es el truco de «no existe oficina» frente a «no tiene empleados».
